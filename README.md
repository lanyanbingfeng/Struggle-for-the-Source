# 争源

《争源》是一款基于 Godot 4.7 的 2D 俯视角策略/资源经营原型。玩家将在地图中围绕基地进行资源建设、单位管理和持续扩张。

当前版本已经完成可配置大小的世界、玩家独立领地、单人人机、领地扩张、房主权威玩法同步、战争迷雾、可缩放战术地图、受击定位提醒、机器升级、卡牌招募、9 级基地成长、五类工人建筑、共享战斗系统、树人/剑士英雄、精英野怪与九格世界 BOSS、局域网大厅和编队移动功能。

## 当前开发进度

### 已完成

- 单人游戏提供小 100×100、中 250×250、大 500×500 三档草地地图，默认大地图；草地使用单个重复纹理绘制，不按格创建 Tile 节点。
- 使用 32×32 逻辑网格计算占地、碰撞和寻路；新生成及玩家提供的高清 PNG 直接作为正式资源，由场景节点等比缩放显示。
- 在地图中放置两块 20×20 Tile 测试领地，每块领地都有独立 3×3 基地。
- 两块领地使用完全相同的相对资源坐标：每边 12 棵树、8 处石头。
- 两块初始测试领地在地图中保持近距离分布；单人局分别属于玩家和人机。
- 基地支持鼠标左键点击检测。
- 点击基地后弹出操作菜单，当前包含：
  - 招募
  - 召唤
  - 升级
- 操作菜单按钮支持统一配置、禁用状态和扩展按钮。
- 菜单按钮从基地操作点移动到最终位置，并执行线性放大动画。
- 基地操作菜单和招募卡牌都保存基地世界节点引用；相机滚动后会持续换算屏幕坐标，不会与基地发生偏移。
- 鼠标移动到屏幕边缘时，相机自动滚动；越靠近边缘，移动速度越快。
- 相机根据地图边界自动限制移动范围。
- 鼠标悬停在实际按钮上时暂停边缘滚屏；基地菜单或卡牌菜单的空白背景允许四向边缘滚屏，普通招募可点击空白取消。
- 1×1 伐木机在卡牌与世界场景中共享同一张高清立绘，世界显示压缩到一格。
- 1×1 采石机使用带银色齿轮的高清卡牌立绘，卡牌与世界场景共享；后续新增与明确替换的资源均直接使用原始高清美术。
- 已建立资源生成与导入规范 v4.0：正式资源保留生成原图，不再强制转换为像素尺寸或硬像素风格。
- 左上角资源 HUD 显示金币、木材、石头、铁、召唤符、技能经验和经验；单人/房主初始金币为 700，足以建立基础工人队伍。
- 基地点击“招募”后会显示伐木机、采石机、探索者和建筑工人卡牌；探索者招募费用为 500 金币，建筑工人为 250 金币。
- 伐木机和采石机出生时默认工作；选中后可切换工作/休息、查看等级和升级费用。休息状态可在所属领地内移动，越界命令会提示并夹到边界。
- 两类机器最高 Lv.4，升级提升移动和采集速度；采石机 Lv.1 采石、Lv.2 采铁、Lv.3 起可开启宝箱。

- 石头被采完后获得 8 石头，不再额外消耗金币。
- 初始领地按同一随机种子生成公平的铁矿与宝箱布局；场景不再生成金矿和钻石矿点。宝箱提供金币、铁和英雄成长资源。

- 支持创建带可选密码的房间；房主可设置 2～4 支队伍、每队 1～4 人、贫瘠/标准/丰富三档资源，以及简单/普通/困难/地狱四档野怪难度。
- 准备界面支持点击空位移动，也支持点击已占座位与对方交换位置；所有玩家准备后房主才能开始游戏。
- 房间、玩家、座位、准备状态和房主设置均由房主权威同步；密码只在连接后交给房主校验，不会通过房间发现广播发送。
- 多人游戏开始时会按房主选择的资源丰富度生成资源，并继续保证两块测试领地的相对布局一致。
- 每名联机玩家由房主分配一个固定 `territory_id` 和独立 20×20 领地；换队不会改变领地所有权。
- 每名玩家只能点击自己的基地。召唤、招募、移动、采集结算和资源消失均由房主校验并同步，客户端提交其他玩家单位 ID 时会被拒绝。
- 已增加半透明战争迷雾：未探索区域仍能隐约看到草地，但无视野的外部资源、敌方领地、基地和单位会被实体裁剪隐藏，不会再透过蒙版泄露位置。

### 当前阶段

目前已经具备可以运行和体验的资源经营、领地扩张、自动生产、野怪掉落和英雄成长闭环；胜负条件与更多野怪/英雄内容仍处于搭建阶段。

“招募”提供伐木机、采石机、探索者和建筑工人卡牌；基地“召唤”提供五张随机战斗单位卡牌；英雄台通过独立面板召唤孔夫子，并由房主验证英雄类别、唯一英雄与召唤符费用。

## 游戏玩法概念

玩家以基地为核心，在地图上收集和管理资源，逐步发展自己的势力。

预期的基础玩法循环如下：

```text
浏览地图
  ↓
查看基地与资源分布
  ↓
点击基地
  ↓
选择招募、五卡召唤或升级
  ↓
消耗资源并获得单位/能力/建筑强化
  ↓
继续扩张和争夺地图资源
```

### 基地操作

点击基地后，会在基地上方显示操作菜单：

- 招募：打开伐木机、采石机、探索者和建筑工人卡牌，可重复生成；出生位置会按招募序号错开。
- 召唤：消耗 10 金币，按当前基地等级概率生成五张纯战斗单位卡牌；费用支付后必须选择其中一张。英雄台的定向英雄召唤仍是独立功能。
- 升级：按当前等级消耗金币、木材、石头和铁并提升至下一级，最高为 Lv.9；悬停按钮可查看下一等级费用。

三个基地操作均已接入实际逻辑，并由房主验证所有权、招募/召唤费用、五卡 offer 和等级；英雄选择、唯一性及召唤符费用由英雄台入口另行验证。

### 玩家领地

- 每名玩家初始拥有一块固定 20×20 Tile（640×640 像素）公平领地；初始位置会按所选地图大小调整，100×100 下也不会越界或互相重叠。
- 所有初始领地的树木、石头、铁矿及宝箱数量和相对坐标完全一致；每轮资源位置随机，但使用房主同步的同一随机种子，确保初始资源绝对公平。
- 基地、机器和战斗单位都带有房主分配的 `owner_peer_id` 与 `territory_id`。
- 玩家本地只启用自己基地的点击区域；服务端还会再次验证每条召唤、招募和移动请求。

### 视野与开发者模式

- 自己的 20×20 领地始终可见，不需要单位提供视野。
- 领地外覆盖约 46% 不透明度的深色战争迷雾，草地轮廓仍然可见。
- 己方单位会按其 `UnitDefinition.vision_radius_tiles` 揭示圆形范围；控制树人离开领地即可探索外部。
- 右上角“开发者：显示全图”只改变本机显示；“开发者：暂停人机”会冻结人机单位与决策，恢复后继续运行。
- “生成 BOSS”和“生成精英”会显示 3×3 或 2×2 占地预览：金色/紫色表示可生成，红色表示被地图边界、基地、建筑或资源阻挡。BOSS 始终保持单局唯一，再次生成会把现有 BOSS 满血重置到新位置；精英可连续追加。多人模式仅房主可执行，并通过可靠 RPC 同步给客户端。
- 世界 BOSS 的 3×3 占地任意一格进入视野即显示模型、名称和顶部血条；开发者全图同样视为可见。
- 视野参数位于 `game/data/*_definition.tres`。在 Godot 文件系统中双击资源后，可直接在 Inspector 调整数值。

### 战斗单位与自动战斗

- 树人和剑士逻辑占地 1 Tile，世界 Sprite 复用高清卡牌立绘并等比缩放到一格；左键点击己方战斗单位会单选，脚下显示红色椭圆选中圈。
- 按住左键拖动会显示红色选择框，释放后选中框内所有己方战斗单位。
- 右键地面会显示扩散圆环，并向房主提交当前选中单位和目标位置。
- 选中一个或多个战斗单位后右键可见宝箱，单位会把宝箱设为玩家指定目标、寻路到攻击距离并攻击开启；领地内实体宝箱和领地外流送宝箱都支持，奖励归最后攻击的玩家。
- 房主使用稀疏障碍路径器保存实际占用格并计算绕行点，不再为百万格地图预分配 `AStarGrid2D`；点击障碍物时会选择最近可通行终点。
- 树人按路径点移动，并由 `StaticBody2D` 物理碰撞提供第二层防穿模保护；多单位移动时按数据中的编队间距形成方阵，避免目标点重叠。
- 敌人第一次进入攻击范围时会从零开始累计攻速时间，离开范围会重置，避免反复进出触发瞬时伤害；追击超过各自配置范围后会回到开战前位置。
- 伤害为攻击减防御且至少为1，闪避由房主判定；单位和建筑生命降至0后通过可靠 RPC 移除。
- 招募池与英雄池配置在 `game/data/unit_catalog.tres`；英雄池只有树人系和剑士战斗单位，不会出现工人。

### 建筑工人和生产建筑

- 选中建筑工人后，右下角显示“建筑”按钮；展开后选择任一建筑都会进入固定 2×2 预览，不预先阻止无效起点。WASD 每次移动一格，预览随校验结果实时显示绿色或红色；红色位置确认时保留预览并提示原因，绿色位置确认后工人寻路到建筑相邻施工位。
- 建筑必须完整位于工人所属的己方领地，不得与基地或已有建筑重叠；资源建筑还必须在配置半径内存在对应资源点。
- 伐木场、采石场和铁矿场生产对应基础资源；金币生产台不需要矿点，只需要木材和石头；英雄台负责召唤与替换英雄。
- 工人到达后才创建建筑实例；施工时工人隐藏并暂停碰撞、移动和视野贡献，完成或工地被移除后在施工位重新出现。
- 所有建筑先经历数据定义的施工时间；ImageGen 通用施工贴图、进度条和剩余秒数在 `production_building` 场景中处理。
- 建筑费用、生命、防御、施工时间、铁升级费用、资源条件、单次产量和生产间隔统一配置在 `game/data/*_definition.tres`，目录为 `game/data/building_catalog.tres`。

### 地图浏览

- 地图采用正交俯视视角。
- 鼠标移动到屏幕四周会触发相机滚屏。
- 鼠标越接近屏幕边缘，滚屏强度越高。
- 相机不会移动到地图范围之外。
- M 键打开/关闭战术地图；详细地图包含资源、战斗单位、基地与生产建筑图例和悬停情报。滚轮缩放，按住左键拖动平移放大区域，短按左键可在不关闭地图的情况下快速移动主视角。
- 操作菜单打开时，将鼠标停留在按钮上不会触发相机滚屏；移动到菜单空白背景时仍可向四个方向滚屏，菜单和招募卡牌会保持跟随基地。

### 局域网多人大厅

- 点击“多人游戏”后进入房间浏览页；搜索会自动持续进行，也可以手动刷新。
- 创建房间时，本机同时作为 ENet 房主；密码可以留空。
- 加入带密码的房间时，在房间详情中输入密码再加入。
- 进入准备界面后，点击目标座位可换位；点击已占用座位会与该玩家交换。
- 房主可在两行设置网格中调整队伍数量、每队人数、资源丰富度和野怪难度；座位容量不能小于当前玩家数。
- 所有玩家（包括房主）都准备后，房主的“开始游戏”按钮才会启用。
- 开始游戏后，房主负责单位 ID、领地归属、出生、移动目标、采集、资源结算和状态快照；客户端负责输入和显示。
- “存档”页列出本机未完成的多人战斗。恢复房间沿用原队伍和规则，原参与者自动认领席位；新玩家需点击“离线·可顶替”席位后才能准备。
- 房主的权威检查点会保存到所有参与电脑。加入者带来更高 `revision` 时房主采用该副本，否则加入者用房主副本替换本机旧记录。

## 运行项目

### 环境要求

- Godot 4.7，当前开发验证版本为 Godot 4.7.2。
- Windows 环境使用项目配置的 Mobile 渲染模式。

### 启动方式

1. 使用 Godot 打开项目目录：

   ```text
   当前仓库根目录（例如 `C:\GodotProjects\Struggle-for-the-Source`）
   ```

2. 打开项目后运行主场景或直接运行项目。
3. 项目主场景配置为 `res://game/main/main.tscn`。

### 两台电脑局域网测试

1. 两台电脑连接到同一个局域网，并分别用 Godot 运行本项目。
2. 电脑 A 选择“多人游戏 → 创建房间”，按需输入密码。
3. 电脑 B 选择“多人游戏”，等待房间自动出现，选中后加入。
4. 如果 Windows 防火墙首次弹窗，请允许 Godot 在专用网络通信。
5. 测试换位、准备和房主设置同步；双方准备后由房主开始游戏。
6. 确认两端镜头位于各自领地，且无法点击另一名玩家的基地。
7. 双方召唤树人并移动；使用右上角“显示全图”检查单位位置同步，再关闭以检查战争迷雾。

房间发现使用 UDP `45454`，游戏连接使用 ENet/UDP `45455`。若无法发现，请确认两台电脑位于同一子网、路由器未开启客户端隔离，并允许这两个 UDP 端口通过防火墙。

也可以使用 Godot 命令行运行：

```powershell
& "<Godot executable path>" --path "<project root>" --editor
```

## 技术配置

- 引擎：Godot 4.7。
- 渲染器：Mobile。
- 纹理过滤：Nearest，关闭默认平滑过滤。
- 窗口视口：640×480。
- 窗口拉伸：`canvas_items`，比例模式为 `expand`。
- 地图：单人局可选 100×100、250×250、500×500 Tile，默认且最大为 500×500；`TileMapLayer` 容器内使用重复草地 `Sprite2D`，避免逐格常驻节点。
- 相机：`Camera2D`。
- 基地交互：`Area2D` + `CollisionShape2D`。
- 菜单层：`CanvasLayer`。
- 局域网发现：`PacketPeerUDP` 广播查询与房主单播响应，UDP 端口 `45454`。
- 多人连接：`ENetMultiplayerPeer`，UDP 端口 `45455`，房主权威房间快照。
- 存档：`GameSaveManager` 使用 `user://saves/` 保存单人固定槽位和按 `game_id` 分文件的多人记录；多人协议 v3 负责恢复身份、版本仲裁和权威检查点同步。
- 玩法同步：服务端权威 RPC；可靠通道同步单位/建筑生成、命令、死亡、BOSS 普攻/技能表现和资源事件，不可靠有序通道每 0.1 秒同步单位位置及单位/建筑/BOSS生命与阶段状态。
- 战争迷雾：按本局地图尺寸配置半透明遮罩，只绘制当前视口内的格；使用每格探索位图永久保存本局已探索范围，并给战术地图提供 GPU 纹理；实体层同步隐藏无视野的敌方基地、单位和资源。
- 战术地图与受击提醒：`TacticalMap`/`TacticalMapView` 读取本地探索纹理，以及经过视野过滤的资源、领地、单位、基地和建筑情报；资源来自 `WorldResourceStreamer` 的只读坐标快照与已实体化资源，已探索资源可保留，敌方实时单位和建筑仅限当前视野。`HealthComponent.damaged` 携带攻击来源说明，由房主通过可靠 RPC 只通知受击单位所属玩家。
- 资源流送：`WorldResourceStreamer` 常驻资源坐标数据，只为摄像机当前区块及周围八块创建 `WorldResourceMarker`；跨区块时卸载旧节点并加载新节点。
- 单位数据：共享 `UnitDefinition` / `UnitCatalog` Godot Resource（`.tres`）；战斗实例只保存当前生命、魔法、目标和冷却等运行时状态。
- 建筑数据：共享 `BuildingDefinition` / `BuildingCatalog` Godot Resource（`.tres`），统一配置费用、条件、生命、防御和周期产出。
- 战斗组件：`HealthComponent` 负责生命、魔法、防御和闪避，`HealthBar2D` 负责单位/建筑世界空间生命条。
- 单位寻路：稀疏障碍格和按需绕行点；内存规模取决于实际障碍数，不取决于地图百万格总量。
- Codex 项目 Skill：`.codex/skills/`。
- Codex 项目 MCP 配置：`.codex/config.toml`。
- 3D 物理引擎配置：Jolt Physics；当前玩法主要为 2D。

## 资源规范

项目使用 32×32 作为逻辑 Tile 网格，但不再限制美术文件分辨率。

- 新生成及玩家指定图片直接保留原始高清 RGBA PNG。
- 世界 Sprite、卡牌、HUD 和建筑气泡可以引用同一正式纹理，并各自等比缩放。
- 默认使用 Linear 过滤；需要远近缩放的世界纹理允许开启 Mipmaps。
- 碰撞、寻路占地与视觉显示尺寸独立配置。
- 生成或修改资源前，必须阅读 [资源生成规范](docs/asset-generation-spec.md)。
