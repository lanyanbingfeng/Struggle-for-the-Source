# 争源

《争源》是一款基于 Godot 4.7 的 2D 像素风俯视角策略/资源经营原型。玩家将在地图中围绕基地进行资源建设、单位管理和持续扩张。

当前版本已经完成双人测试领地、基地交互、可重复招募、两类自动采集机器、局域网大厅和相机浏览功能，属于“资源采集与联机大厅原型”阶段。

## 当前开发进度

### 已完成

- 创建 100×100 Tile 的草地地图，地图尺寸为 3200×3200 像素。
- 使用 32×32 像素网格和 Nearest 像素导入配置。
- 在地图中放置两块 20×20 Tile 测试领地，每块领地都有独立 3×3 基地。
- 两块领地使用完全相同的相对资源坐标：每边 12 棵树、8 处石头。
- 两块测试领地在场景中左右相邻，初始镜头会同时框住两个基地，便于直接确认玩家2领地。
- 基地支持鼠标左键点击检测。
- 点击基地后弹出操作菜单，当前包含：
  - 招募
  - 召唤
  - 升级
- 操作菜单按钮支持统一配置、禁用状态和扩展按钮。
- 菜单按钮从基地操作点移动到最终位置，并执行线性放大动画。
- 鼠标移动到屏幕边缘时，相机自动滚动；越靠近边缘，移动速度越快。
- 相机根据地图边界自动限制移动范围。
- 鼠标悬停在 UI 控件上时，暂停边缘滚屏，避免操作菜单打开时误移动镜头。
- 已升级 1×1 伐木机器资源，车体为 32×32 像素，并使用独立 11×11 锯片节点播放工作旋转。
- 已增加 1×1 采石机器资源、独立旋转矿轮和 32×32 石头资源。
- 已建立项目资源生成与导入规范，统一使用正交俯视角、左上光源和硬像素边缘。
- 已增加左上角资源 HUD，显示金币、木材、石头和铁矿；金币开发模式初始值为 9999。
- 基地点击“招募”后会进入单位选择，可选择伐木机或采石机；同类型机器可以重复招募。
- 伐木机只寻找本玩家领地内的树，采石机只寻找本玩家领地内的石头。
- 伐木机器在树边每秒调用一次树木砍伐入口，三次后复用现有倒下动画。
- 树木倒下并完成动画后，木材增加 10，金币减少 1。
- 石头被采完后，石头增加 8，金币减少 1。
- 已增加带像素风背景的全屏开始界面，支持单人游戏、多人游戏、设置、关于和退出游戏。
- 多人游戏会打开局域网大厅，自动发现同一局域网内由其他玩家创建的房间。
- 支持创建带可选密码的房间；房主可设置 2～4 支队伍、每队 1～4 人以及贫瘠/标准/丰富三档资源。
- 准备界面支持点击空位移动，也支持点击已占座位与对方交换位置；所有玩家准备后房主才能开始游戏。
- 房间、玩家、座位、准备状态和房主设置均由房主权威同步；密码只在连接后交给房主校验，不会通过房间发现广播发送。
- 多人游戏开始时会按房主选择的资源丰富度生成资源，并继续保证两块测试领地的相对布局一致。
- 已增加游戏内 Esc 菜单，支持返回游戏、设置、返回主菜单和退出游戏。
- 单人模式打开 Esc 菜单时暂停游戏时间；多人模式打开菜单时游戏继续运行。
- 从游戏返回主菜单会离开当前局域网房间、清理当前单位、重置开发资源、按公平布局重生树木和石头，并将相机复位到双领地概览。

### 当前阶段

目前已经具备可以运行和体验的基础交互 Demo，但核心策略玩法仍处于搭建阶段。

“招募”“召唤”“升级”均已完成按钮、信号和事件分发流程；其中“招募”提供伐木机/采石机二级选择，两类机器均已接入领地内自动采集，资源结算由资源管理器统一处理。

## 游戏玩法概念

玩家以基地为核心，在地图上收集和管理资源，逐步发展自己的势力。

预期的基础玩法循环如下：

```text
浏览地图
  ↓
查看基地与资源分布
  ↓
点击基地
  ↓
选择招募、召唤或升级
  ↓
消耗资源并获得单位/能力/建筑强化
  ↓
继续扩张和争夺地图资源
```

### 基地操作

点击基地后，会在基地上方显示操作菜单：

- 招募：打开二级选择菜单，可重复生成伐木机或采石机；出生位置会按招募序号错开。
- 召唤：计划用于召唤特殊单位、资源或战斗力量。
- 升级：计划用于提升基地等级、解锁能力或增强生产效率。

目前“召唤”和“升级”仍属于功能入口；“招募”已经接入伐木与采石机器生成及自动采集流程。

### 玩家领地

- 测试地图放置玩家1、玩家2两块领地，每块固定为 20×20 Tile（640×640 像素）。
- 两块领地的树木和石头数量、相对坐标完全一致，确保初始资源绝对公平。
- 机器带有 `territory_id`，只会选择所属领地中可采集的目标。

### 地图浏览

- 地图采用正交俯视视角。
- 鼠标移动到屏幕四周会触发相机滚屏。
- 鼠标越接近屏幕边缘，滚屏强度越高。
- 相机不会移动到地图范围之外。
- 操作菜单打开时，将鼠标停留在按钮上不会触发相机滚屏。

### 局域网多人大厅

- 点击“多人游戏”后进入房间浏览页；搜索会自动持续进行，也可以手动刷新。
- 创建房间时，本机同时作为 ENet 房主；密码可以留空。
- 加入带密码的房间时，在房间详情中输入密码再加入。
- 进入准备界面后，点击目标座位可换位；点击已占用座位会与该玩家交换。
- 房主可调整队伍数量、每队人数和资源丰富度；座位容量不能小于当前玩家数。
- 所有玩家（包括房主）都准备后，房主的“开始游戏”按钮才会启用。

## 操作方式

| 操作 | 说明 |
|---|---|
| 开始界面“单人游戏” | 进入单人地图，Esc 菜单会暂停时间 |

| 准备/取消准备 | 切换本玩家准备状态 |

| 鼠标左键点击基地 | 打开或关闭基地操作菜单 |
| 鼠标移动到屏幕边缘 | 移动地图视角 |
| 点击“招募” | 打开伐木机、采石机和返回三个选项 |

## 运行项目

### 环境要求

- Godot 4.7，当前开发验证版本为 Godot 4.7.2。
- Windows 环境使用项目配置的 Mobile 渲染模式。

### 启动方式

1. 使用 Godot 打开项目目录：

   ```text
   当前仓库根目录（例如 `C:\GodotProjects\Struggle-for-the-Source`）
   ```

2. 打开项目后运行主场景或直接运行项目。
3. 项目主场景配置为 `res://game/main/main.tscn`。

### 两台电脑局域网测试

1. 两台电脑连接到同一个局域网，并分别用 Godot 运行本项目。
2. 电脑 A 选择“多人游戏 → 创建房间”，按需输入密码。
3. 电脑 B 选择“多人游戏”，等待房间自动出现，选中后加入。
4. 如果 Windows 防火墙首次弹窗，请允许 Godot 在专用网络通信。
5. 测试换位、准备和房主设置同步；双方准备后由房主开始游戏。

房间发现使用 UDP `45454`，游戏连接使用 ENet/UDP `45455`。若无法发现，请确认两台电脑位于同一子网、路由器未开启客户端隔离，并允许这两个 UDP 端口通过防火墙。

也可以使用 Godot 命令行运行：

```powershell
& "<Godot executable path>" --path "<project root>" --editor
```

## 技术配置

- 引擎：Godot 4.7。
- 渲染器：Mobile。
- 纹理过滤：Nearest，关闭默认平滑过滤。
- 窗口视口：640×480。
- 窗口拉伸：`canvas_items`，比例模式为 `expand`。
- 地图：`TileMapLayer`。
- 相机：`Camera2D`。
- 基地交互：`Area2D` + `CollisionShape2D`。
- 菜单层：`CanvasLayer`。
- 局域网发现：`PacketPeerUDP` 广播查询与房主单播响应，UDP 端口 `45454`。
- 多人连接：`ENetMultiplayerPeer`，UDP 端口 `45455`，房主权威房间快照。
- Codex 项目 Skill：`.codex/skills/`。
- Codex 项目 MCP 配置：`.codex/config.toml`。
- 3D 物理引擎配置：Jolt Physics；当前玩法主要为 2D。

## 资源规范

项目使用 32×32 像素作为基础 Tile 网格。

- 1×1 资源：32×32 像素。
- 3×3 资源：96×96 像素。
- Ground 使用不透明 PNG，并保持四边可平铺。
- 建筑、单位、资源和装饰使用透明 RGBA PNG。
- 像素资源关闭 Filter 和 Mipmaps，按用途配置 Repeat。
- 禁止使用运行时缩放弥补错误的资源尺寸。
- 生成或修改资源前，必须阅读 [资源生成规范](docs/asset-generation-spec.md)。
