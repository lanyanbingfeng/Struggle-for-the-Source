# 区块资源流送、迷雾实体裁剪与纯战斗召唤池

## 已确认实现

- 半透明战争迷雾只负责压暗未探索草地；`map_demo.gd` 每次刷新视野后，会独立裁剪外部资源、敌方领地、敌方基地和敌方单位。没有视野时这些实体的 `visible` 为 `false`，开发者全图模式才恢复显示。
- `unit_catalog.tres` 的 `summon_pool` 只登记树人、铁木树人、远古树人和世界根守卫。`UnitCatalog._definitions_for_rarity()` 还会按 `Category.COMBAT` 二次过滤，工人即使被误加入资源池也不会被抽到。
- 本实现替代 `memory/2026-08-24-large-world-ai-machine-explorer.md` 中“全图约2500个常驻轻量标记”的旧方案。
- `WorldResourceStreamer` 把1000×1000地图分成32×32 Tile区块。全图资源只以字典数据常驻；摄像机所在区块和周围八块组成3×3加载区，跨区块时同步卸载旧标记、加载新标记。
- 标准资源档实测约2.9万条资源数据，但九宫格只实例化约230～270个 `WorldResourceMarker`，移动到远端区块后旧/新加载资源ID无重叠。
- 每个标准区块生成1～2个5～9棵的小树林和9～14个零散石头；铁矿群出现率和群规模最高，金矿群其次，钻石群最低。丰富度仍会调整树林、散石和矿群数量。
- 探索者预览直接统计数据层资源；确认领地后，覆盖范围内的数据会从流送器移除并转换为带采集脚本和碰撞的正式资源节点，不依赖该区块是否正在显示。

## 关键文件

- 数据生成、区块索引和加载卸载：`game/world/world_resource_streamer.gd`
- 轻量显示节点：`game/world/world_resource_marker.gd`
- 视野实体裁剪、扩张资源实体化：`game/main/map_demo.gd`
- 召唤池与防御性类别过滤：`game/data/unit_catalog.tres`、`game/data/unit_catalog.gd`

## 验证记录

- Godot 4.7.2 专项单人局检查：标准档总资源29714，其中树木9663、石头11578、铁矿6060、金矿1993、钻石420；铁矿 > 金矿 > 钻石。
- 树木、铁矿、金矿、钻石的同类成群比例均大于99%，满足小树林和矿群布局。
- 初始九宫格加载229个标记，远端九宫格加载262个标记，活动区块始终为9，两个位置的资源ID重叠为0。
- 无视野时敌方基地、敌方单位、敌方资源和外部资源均隐藏；己方领地资源可见；开发者全图模式全部恢复。
- 对Lv.1～Lv.9执行1350张召唤卡抽取，全部为战斗单位。
- 20×20扩张范围测试在数据层统计12个资源，领地接管后数据计数归零并实体化12个可采集资源。

## 手动复验

1. 单人游戏不开全图，滚屏到敌方方向，确认只能看到半透明草地，不能看到敌方基地、单位、领地轮廓和资源。
2. 开启“显示全图”，确认摄像机附近资源与敌方实体出现；快速连续滚动，确认区块边缘不会短暂空白。
3. 多次点击召唤，确认卡牌只有战斗树人，不出现伐木机、采石机或探索者。
4. 浏览外部地图，确认树木呈小树林、石头大量散布，铁矿群明显多于金矿群，钻石群最少。
