# 公平领地、可重复招募与双采集机器

- 领地规则：测试地图固定放置两块 20×20 Tile（640×640 像素）领地；每块使用相同的领地内相对坐标生成 12 棵树和 8 处石头，初始数量与布局绝对一致。资源节点和采集机器使用 `territory_id` 隔离目标。
- 招募修复：删除地图对单个 `_lumber_machine` 的唯一实例限制；每次选择单位都实例化新节点，并按全局招募序号错开基地门口出生位置，避免不同机型重叠。基地“招募”现在打开伐木机、采石机、返回三个二级选项。
- 伐木机器：逻辑/视觉占地保持 1×1 Tile，车体 PNG 为 32×32；独立锯片 PNG 为 11×11，在 `CHOPPING` 状态旋转，离开工作状态自动归位。机器没有独立物理碰撞体，采集距离由脚本工作点控制。
- 石头与采石机器：石头为 1×1 Tile、32×32 RGBA 资源，碰撞区域 28×24；四次命中后结算石头 +8、金币 -1。采石机器车体为 32×32，独立矿轮为 11×11，自动寻找本领地最近石头并在 `MINING` 状态旋转。
- 美术来源：石头使用内置图片生成后按最近邻处理为原生 32×32，并二值化 alpha；透明机器生成端点连续网络失败，未切换需要 API 密钥的 CLI，伐木车体/锯片从已生成概念图机械提取，采石机沿用同一底盘视觉语言制作蓝钢/铜色变体。
- 导入约定：新增 PNG 均关闭 Mipmaps，场景节点使用 Nearest 过滤；Repeat 关闭。Sprite 不使用运行时缩放。
- 验证方式：Godot 4.7.2 MCP 启动无错误；一次性 headless 烟雾测试验证 2 个领地、树 12+12、石 8+8、连续招募 2 台伐木机与 1 台采石机、锯片/矿轮旋转，以及木材和石头各完成一次结算。临时测试脚本、场景和日志已逐文件删除。
