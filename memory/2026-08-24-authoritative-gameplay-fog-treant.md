# 权威领地同步、战争迷雾与树人编队

## 联机所有权与同步协议

- `LanSession` 在玩家加入时分配不重复的 `territory_id`；领地编号不随准备界面的队伍/席位交换改变。
- `game/main/map_demo.gd` 使用房主权威玩法协议。客户端只提交单位定义 ID、自己的单位 ID 列表和目标位置；房主从 RPC 的远端发送者 ID 推导玩家身份，不接受客户端自报领地或所有者。
- 召唤/招募时，房主验证玩家存在、领地确实属于请求者，再生成全局递增单位 ID、出生位置和所有权数据并可靠广播。
- 移动时，房主逐个验证单位的 `owner_peer_id` 和战斗单位类别；其他玩家的单位 ID 会被忽略，全部无效时请求返回失败。
- 单位生成、编队目标、资源移除和资源结算使用可靠 RPC；单位位置/工作状态每 0.1 秒使用不可靠有序通道同步。
- 伐木机和采石机只在房主端模拟。客户端接收位置/工作动画、资源节点移除和仅属于本玩家的资源状态。
- 地图使用 4×4 领地布局，最多 16 块；每块固定 20×20 Tile，资源相对坐标与丰富度完全一致。
- 运行时每名玩家获得独立 `PlayerBase`；只有本地玩家基地的 `Area2D.input_pickable` 启用，服务端权限校验作为第二层保护。

## 数据驱动单位配置

- `game/data/unit_definition.gd` 是 Godot 版 Unity ScriptableObject：对应 `.tres` 可在 Inspector 直接编辑显示名、类别、场景、卡牌纹理、视野格数、移动速度、占地和编队间距。
- `game/data/unit_catalog.tres` 登记全部单位并维护 `summon_pool`。召唤界面固定请求五张卡，按池中条目循环生成；当前池中只有树人，所以五张都是树人。
- 当前定义文件为 `lumber_machine_definition.tres`、`quarry_machine_definition.tres` 和 `treant_definition.tres`。树人视野当前为 7 Tile、速度 92 px/s、编队间距 42 px。

## 战争迷雾与开发者模式

- `FogOfWar` 以不透明 Tile 遮罩覆盖不可见区域；本地玩家整块领地始终可见。
- 只有 `owner_peer_id` 等于本地玩家的单位成为视野源，半径来自单位定义；战斗单位离开领地后可揭示外部地图和资源。
- 右上角 `DeveloperPanel` 的“开发者：显示全图”只关闭本机遮罩，不改变房主状态；返回主菜单时自动恢复关闭。

## 树人、选择与移动

- 树人视觉资源为 `art/units/unit_treant_1x1.png`：原生 32×32、RGBA8、透明背景、正交俯视、左上光源；逻辑占地 1 Tile，圆形碰撞半径 11 px。
- AI 生成图只作为树冠/树干造型参考，正式资源重新按原生 32×32 像素块设计，没有把复杂大图直接缩小进项目。
- 左键点选和按住左键框选都只收集本玩家战斗单位；选中树人脚下绘制红色椭圆。
- 右键显示扩散圆环并提交移动命令。树人不使用寻路，按速度直线 `move_and_slide()`；多选时房主按平方根列数生成居中的方阵目标，并按地图边界裁剪，目标点不会重叠。

## 验证记录

- 单进程结构测试确认：两名玩家分别拥有领地 1/2；敌方基地不可点击；敌方领地受迷雾遮挡；开发者全图有效；召唤菜单生成五张卡；五个树人编队目标互不重叠；玩家 1 无法移动玩家 2 的树人。
- 双 Godot 4.7.2 进程测试确认：客户端获分领地 2；伪造的房主树人移动命令被拒绝；客户端树人生成/移动同步；客户端伐木机仅在房主端模拟，采集后双方移除同一树节点，客户端木材同步为 10。
- 房主和客户端均输出 `GAMEPLAY_NETWORK_SMOKE PASS`，日志无脚本或网络错误；临时测试场景、日志和 UID 已逐个清理。

## 人工复验

1. 两台电脑分别进入同一房间并开始游戏，确认镜头落在各自基地，另一领地不可见且另一基地不可点击。
2. 点击己方基地的“召唤”，确认基地上方出现五张树人卡；选择任意卡召唤。
3. 左键点选树人，确认红圈；拖框选多个树人，右键地图，确认目标圆环与分散编队移动。
4. 控制树人走出领地，确认它周围逐格揭示外部，远处仍为黑色。
5. 开启右上角“显示全图”，比较两端单位和资源位置；关闭后确认迷雾恢复。
