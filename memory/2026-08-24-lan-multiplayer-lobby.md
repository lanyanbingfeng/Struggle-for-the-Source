# 局域网多人大厅与准备同步

## 已确认实现

- 开始界面的“多人游戏”不再直接进入地图，而是打开 `game/ui/lan_lobby.tscn`。
- `game/systems/lan_session.gd` 负责局域网发现、ENet 连接、密码校验和房间状态同步。
- 房间浏览客户端绑定随机 UDP 端口并向 `255.255.255.255:45454` 周期广播查询；房主固定绑定 UDP `45454` 并向查询来源单播房间信息。
- 游戏连接使用 `ENetMultiplayerPeer` 和 UDP `45455`。同一台电脑只能创建一个使用默认端口的房间，但可同时运行客户端完成本机双进程测试。
- 房间密码不会出现在发现广播中；客户端连接后通过可靠 RPC 提交，房主校验失败后拒绝并断开。
- 房主权威维护队伍数、每队人数、资源丰富度、玩家座位和准备状态，并向客户端广播完整快照。
- 队伍数范围为 2～4，每队人数范围为 1～4，资源丰富度为贫瘠/标准/丰富三档。
- 点击空座可移动，点击已占座位会与目标玩家交换；所有玩家（含房主）准备后才能开始游戏。
- 开始游戏快照会把资源丰富度交给地图：贫瘠为每块领地 8 棵树/5 处石头，标准为 12/8，丰富为 16/12；两块测试领地始终使用完全相同的相对坐标。
- 离开房间或返回主菜单会关闭 ENet/UDP 会话并释放端口。

## 验证记录

- 使用 Godot 4.7.2 启动主场景，脚本解析和运行日志无错误。
- 使用两个独立 Godot 4.7.2 进程执行局域网冒烟测试，已验证：自动发现、错误密码拒绝、正确密码加入、房主设置同步、客户端换位、双方准备和房主开始游戏。
- 第二轮冒烟测试的房主与客户端均输出 `LAN_SMOKE PASS`，且日志中无脚本错误或网络错误；临时测试场景和日志已逐个清理。

## 人工复验

1. 两台电脑位于同一局域网，分别从 Godot 运行项目。
2. 电脑 A 创建带密码房间，电脑 B 在多人大厅等待自动发现后加入。
3. 验证错误密码被拒绝，正确密码进入准备界面。
4. 验证房主调整三项设置后客户端即时更新，并测试空位移动与占位交换。
5. 双方准备，由房主开始；确认两端进入地图且资源数量符合所选丰富度。
