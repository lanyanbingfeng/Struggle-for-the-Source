# 九级基地召唤、卡牌招募与稀有矿物

## 基地菜单与卡牌交互

- 基地操作菜单和召唤卡牌菜单使用全屏空白 `Button` 接收关闭点击；空白背景带有 `allow_edge_scroll` 元数据，`EdgeScrollCamera` 会忽略该控制及其子级，因此打开基地后仍可向四个方向边缘滚屏。
- 实际操作按钮和卡牌仍会阻止边缘滚屏，避免鼠标悬停选择时移动镜头。
- “招募”直接打开伐木机与采石机两张数据驱动卡牌，不再进入带“返回”的二级按钮菜单；点击卡牌外空白区域关闭。

## 召唤与基地等级

- `BaseProgression` 定义 9 个基地等级、10 金币召唤费用、每次 5 张卡牌、品质概率与升级费用。
- 召唤概率从 Lv.1 的 `100/0/0/0/0` 逐步变化到 Lv.9 的 `9/15/30/30/16`，对应普通、优秀、稀有、史诗、传说；各等级概率总和均为 100%。
- 召唤费用由房主在生成卡牌前立即扣除，关闭卡牌菜单不会退款；房主保存一次性 `offer_id` 和允许的卡牌 ID，客户端只能选择当前付费结果中的一个单位。
- 当前 `summon_pool` 的五个品质均有有效定义：普通为两类机器，优秀为树人，稀有/史诗/传说分别为铁木树人、远古树人、世界根守卫。高品质树人沿用树人场景和卡牌插画，但使用独立名称与属性；若将来某品质池暂时为空，`UnitCatalog` 会向相邻有效品质回退。
- 基地升级由房主校验六种资源并广播等级；最高 Lv.9。标准资源档完整采集一块领地可覆盖 1→9 的总材料需求：木材 100、石头 60、铁矿 28、金矿 9、钻石 1，另需金币 7300。

## 稀有矿物与公平生成

- 铁矿、金矿和钻石均为原生 32×32 RGBA 像素资源，逻辑/碰撞占地为 1×1 Tile；正交俯视、左上光源、Nearest、无 Mipmaps。
- 房主开始游戏时把 `resource_seed` 写入房间快照。所有端使用相同种子在领地内部随机选择矿点，再把同一相对布局复制到每块 20×20 领地，因此每轮位置随机但玩家资源绝对公平。
- 标准档每块领地生成铁矿 5、金矿 3、钻石 1；贫瘠档为 3/1/1，丰富档为 8/5/2。稀有度数量关系始终为铁矿多于金矿、金矿不少于钻石。
- 采石机的目标根节点为 `Mineables`，会递归寻找本领地内 `stone`、`iron`、`gold_ore`、`diamond`。矿物采完分别获得铁矿 6、金矿 3、钻石 1，并消耗金币 1。
- 资源状态与 HUD 已扩展为金币、木材、石头、铁矿、金矿、钻石六项；稀有矿物也参与 A* 障碍重建和权威资源消失同步。

## 验证

- 单进程目标回归覆盖：四向边缘强度、空白背景滚屏放行、机器卡牌、无返回按钮、10 金币扣费不退款、五卡 offer、1～9 级概率和升级、随机矿点镜像公平、采石机矿物目标与钻石奖励，输出 `GOAL_REGRESSION PASS`。
- 两个独立 Godot 4.7.2 进程完成 ENet 回归：客户端付费召唤、服务端验证并同步单位、六资源状态和基地升级均通过，输出 `NETWORK_GOAL_HOST PASS` 与 `NETWORK_GOAL_CLIENT PASS`。
- Godot MCP 运行视觉检查确认六资源 HUD、两块测试领地、机器卡牌与三种矿物均可见，运行日志无错误。
