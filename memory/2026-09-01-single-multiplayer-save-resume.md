# 单人自动存档与多人战斗恢复

## 已确认实现

- `game/systems/game_save_manager.gd` 负责 `user://saves/` 下的二进制本地存档、格式校验、设备身份和多人存档列表；单人使用固定槽位，多人按稳定 `game_id` 分文件保存。
- 游戏进行中每 5 秒生成一次权威检查点；从暂停菜单退出、返回主菜单或收到窗口关闭请求时会再次保存。多人客户端退出前会向房主请求最新检查点，并以 1.5 秒超时回退到本机最近一次有效副本。
- 单人主菜单发现未完成存档时先显示“继续游戏 / 新游戏”；继续会恢复原世界，新游戏进入现有难度、地图大小和野怪强度设置，并在开局检查点覆盖旧进度。
- 世界存档包含玩家资源、基地等级与生命、扩张领地、单位位置/生命/星级、英雄等级与技能数据、机器状态、建筑等级/建造和生产进度、领地内剩余资源、流送资源、树木再生队列、野怪及世界 BOSS 状态和运行时递增 ID。

## 多人恢复协议

- 局域网协议版本提升为 v3。多人检查点由房主构建，并可靠同步到所有参与电脑；每份记录包含相同 `game_id` 和单调递增 `revision`。
- 多人大厅新增“存档”入口。选择本机存档会创建可被局域网发现的恢复房间，房间列表显示存档版本；恢复房间固定沿用原战斗设置和席位。
- 加入恢复房间时会携带本机稳定设备身份和同局本地副本。若加入者的 `revision` 更高，房主采用并转发该副本；否则加入者接收房主当前副本并覆盖本机旧记录，因此房间始终以已加入成员中的最高版本为准。
- 原参与者按设备身份自动认领原席位；没有该存档身份的玩家先以未绑定状态进入准备界面，只能选择一个离线席位执行“顶替”。顶替保留原席位的队伍、领地和世界归属，但后续检查点把参与者身份改为新玩家。
- 恢复战斗要求所有保留席位都已连接并准备，且不能存在未绑定玩家。恢复开局后，旧会话的 peer ID 会按主领地映射到当前连接者，确保 A/C 顶替或 A/B 再次组合时单位、资源和领地归属正确。

## 验证记录

- Godot MCP 使用 4.7.2 启动 `res://game/main/main.tscn`，无脚本解析错误和运行错误。
- `SAVE_SYSTEM_SMOKE_TEST: PASS`：验证多人文件写入/读取、旧版本拒绝、新版本覆盖、世界状态往返，以及玩家 C 顶替玩家 B 后仍继承原领地席位。
- `AI_DIFFICULTY_SMOKE_TEST: PASS`、`MAP_SIZE_SETTINGS_SMOKE_TEST: PASS`、`GAMEPLAY_REGRESSION_OK`、`BUILDING_CHEST_INTERACTION_REGRESSION_OK`、`WORLD_BOSS_REGRESSION_OK`。

## 手动复验

1. 单人开局后改变资源、单位位置或建筑进度，退出并重开；点击“单人游戏”，分别验证“继续游戏”和“新游戏”。
2. A、B 完成一次多人开局并分别退出，确认两台电脑的大厅“存档”中出现同一战斗；A 创建恢复房间，B 加入并准备后继续。
3. 让 C 在没有该局存档的电脑加入 A 的恢复房间，点击 B 的离线席位顶替，继续并退出；确认新检查点保存在 A、C 电脑。
4. 再由 A 用最新记录创建房间，让仍持旧记录的 B 加入；确认房间显示最新版本，B 本机旧文件被更新，且 B 需要顶替当前离线席位后才能开始。
