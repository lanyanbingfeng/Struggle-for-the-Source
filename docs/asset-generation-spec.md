# 争源资源生成与导入规范 v4.0

## 一、核心原则：原始美术直接使用

从 v4.0 起，所有新生成或由玩家提供的美术资源均保留并直接使用原始高清 PNG。项目不再要求把资源转换为像素风、占地×32 的文件尺寸、硬像素边缘、有限色阶或 Nearest 重采样。

- AI 生成结果通过主体、构图、透明度和游戏内可读性检查后，直接作为正式资源。
- 玩家明确提供并指定使用的图片视为已确认外观，只检查格式、透明度和引用，不重新生成或改变造型。
- 禁止为了卡牌、世界单位、HUD 或建筑气泡另存缩小副本；同一美术应尽量共享同一张正式纹理。
- 不拉伸、不改变宽高比；各场景通过节点尺寸或等比缩放适配显示区域。
- 不得带有无关文字、边框、水印、底色或脏边。需要透明背景的资源必须是有效 RGBA。

## 二、逻辑尺寸与视觉尺寸

- 项目仍使用 `1 Tile = 32×32` 作为逻辑网格，但它只定义占地、碰撞、寻路、距离与布局。
- 纹理文件分辨率不受 Tile 网格限制；逻辑占地和视觉尺寸必须分别配置。
- 世界物体的 Pivot、碰撞形状和寻路占地按玩法单独设定，不从图片分辨率自动推导。
- 同一张高清纹理可同时用于卡牌和世界 Sprite；世界侧只做等比缩放、阵营染色或确有需要的整体翻转。

## 三、生成要求

每次生成前应明确：

- 使用位置：世界、卡牌、HUD、气泡、菜单背景或特效。
- 主体和关键辨识特征。
- 是否需要透明 RGBA 背景。
- 构图方向、视角、光源和风格；这些由具体玩法决定，不再全局限定为正交俯视或左上光源。
- 禁止文字、水印、UI 框和无关场景元素。
- 输出为可直接使用的高清原图，不要求制作低分辨率像素版。

只有用户或具体功能明确要求像素风时，才在该资源的提示词与验收中加入像素风约束；像素风不再是项目默认规范。

## 四、Godot 导入与显示

- 高清资源默认使用 Linear 过滤；需要明显远近缩放的世界纹理可以启用 Mipmaps。
- 重复地面等特殊纹理按具体用途配置 Repeat，不设统一值。
- `Sprite2D` 使用等比 `scale`，UI 使用保持宽高比的 Stretch Mode，禁止非等比拉伸。
- 卡牌、世界单位、HUD 和气泡共享纹理时，各节点只保存自己的显示尺寸，不复制源文件。
- 导入后确认 Godot 能加载纹理，透明边缘正常，运行时无资源缺失或解析错误。

## 五、验收清单

- [ ] 使用的是生成或玩家提供的原始高清 PNG，没有额外缩小副本。
- [ ] 图片尺寸、RGBA/透明度与用途相符。
- [ ] 主体完整、构图清楚，在实际显示尺寸下可以辨认。
- [ ] 没有无关文字、水印、底色、白边或透明脏边。
- [ ] 世界、卡牌、HUD 和气泡按需共享同一正式纹理。
- [ ] Godot 中保持宽高比，过滤方式与实际缩放用途相符。
- [ ] 逻辑占地、碰撞、Pivot 与视觉尺寸分别验证。
- [ ] 主场景启动后没有资源加载、脚本解析或运行时错误。

## 六、版本替代关系

本规范完全替代 v3.0 及更早版本中的原生像素尺寸、占地×32 文件尺寸、硬像素边缘、统一俯视角、统一左上光源、Nearest 重采样与关闭 Mipmaps 等默认要求。历史资源无需批量返工；后续新资源和明确修改的旧资源一律按 v4.0 执行。
